# Phase 12 plan — terminal modes

Implementation plan for phase 12 of [the osrlib spec](spec.md): `SessionMode.VICTORY` with its command-legality rules, and non-battle party wipes routing to `GAME_OVER` — the terminal-state machinery opened once for both changes. Victory becomes *reachable* in phase 15, when completing a concluding quest transitions into it; this phase ships the mode, its legality contract, and the shared wipe machinery that phase 15's transition will stand beside. Phase 12 is order-independent of phase 13 and must land before phase 15. The milestone: **a trap or deprivation wipe ends the session in game-over, and mode-legality tests hold for victory.**

Five facts shape the design:

- **The legality machinery is already data, so the victory half of the phase is almost entirely one enum member plus tests.** Every play command declares an explicit `allowed_modes` frozenset that cannot contain a value that does not exist, and every referee command inherits `_ALL_MODES = frozenset(SessionMode)`, computed at import from the enum itself — so adding `VICTORY` makes play commands illegal and referee commands legal in it by construction, with no dispatch changes. Persistence restores the mode by enum value (`SessionMode(str(payload["mode"]))`) and `PlayerView.mode` is a plain string, so both carry the new value untouched. A new serialized enum value is the additive case the spec's versioning rules name explicitly: no `schema_version` bump, no migration, and an older engine failing to load a `victory` save is the documented accepted risk.
- **Three referee commands can resume play, and terminal means they must not.** `PlaceParty` flips the mode to `exploring` or `town`, and `SpawnMonsters` and `SpawnNpcParty` open an encounter through `start_encounter`, which sets the mode to `encounter` — and an attacks-stance reaction can carry it straight into `battle`, from which `end_encounter` lands back in `exploring`. Leave any of the three legal in `victory` and the mode is not terminal: play resumes through a referee door, which is exactly the post-victory play the spec puts out of scope by decision, with a rationale that decides the tension in its own words — "a post-victory mode can arrive additively later where shipping 'continue' first and tightening later could not." The two spawn commands are excluded from *both* terminal modes, because a concluded session opens no new play state — the same invariant the wiped-party guards enforce against the engine's own procedures, and an encounter among corpses is that state whether a procedure or a referee opens it. `PlaceParty` alone stays legal in `game_over`, because its escape is load-bearing, documented machinery rather than an oversight: the sessions guide is explicit that referee commands run there ("a referee correcting the world doesn't stop just because the party fell"), and `PlaceParty(town)` → `PurchaseHealing(service="raise_dead")` — a real, implemented temple service with `DeathRecord` tracking the revival window — is the working revival flow. Victory has nothing to salvage, so `PlaceParty` is illegal there. Every other referee command — grants, awards, flags, door writes, identification, time, dice — mutates without resuming play and is legal in both terminal modes, which is also what lets phase 15's rewards land after the transition, exactly as the spec requires. The spawn exclusion narrows today's documented `game_over` behavior (a changelog `Changed` entry), and the spec's "referee commands remain legal" sentence gains the matching carve-out — a one-sentence amendment applied with the implementation PR, because a front end predicting legality from the spec should predict this.
- **The salvage flow forces the wipe check to be edge-triggered.** The naive rule — after any command, no living members means game-over — would flip the salvaged session straight back: `PlaceParty(town)` executed from `game_over` leaves zero living members, and a level-triggered check would re-enter `game_over` before the temple could act, deadlocking the documented revival flow. The wipe check therefore fires only when the command's own events contain a `DeathEvent` targeting a party member — the exact walk `_record_deaths` already performs in `execute()` — and the party is then without living members. A wipe is an edge (someone just died); a dead party being ferried to the temple is a state, and states don't re-trigger.
- **The defeat transition gets one home.** Battle's `_check_ends` currently owns the only wipe routing: it flips the mode and emits `GameOverEvent(reason="the party has fallen")` itself. Moving both into the session-level check makes every wipe — battle, trap, deprivation, poison in town — one code path with one reason string, and it is event-stream-neutral where anything looks: all five `_check_ends` call sites (two in `start_battle`, three in the resolve-round handler) place the returned end events in tail position and stop, so for `ResolveBattleRound` — the only command any test or golden resolves a TPK through — a centrally appended `GameOverEvent` lands immediately after `BattleEndedEvent(code="battle.ended.defeat")`, byte-identical to today's stream. One corner does move: a TPK during a battle *started mid-command* (a keyed ambush's free round inside `MoveParty`) today emits `GameOverEvent` where the encounter check runs, before the movement-accrual events; post-fold it lands last, after them. Nothing asserts that path — no stored golden or test reaches a mid-command TPK — and last is where an ending belongs, so the move is recorded here rather than worked around.
- **A wipe mid-command must not leave the rest of the handler initiating new activity for corpses.** Handlers keep running after a death resolves. The trap procedures already guard themselves — `_room_trap_check` states the principle ("a trap needs a living victim: a party with no one left standing rolls no spring die at all") and `_door_trap_check` follows it — but the rest of the mid-command surface does not: a chute trap that kills the whole party still relocates the bodies and then discovers the destination's treasure (drawing on the treasure stream) and opens its keyed encounter; a deprivation wipe mid-`Rest` keeps advancing the span, wandering cadence included; and an encounter round that kills the last member mid-`Wait` continues into stance actions — a hostile deadline starts a battle among corpses, an uncertain stance draws a reaction re-roll for the dead — with `_pursuit_round` sharing the same shape (the distraction draw, the gap update, the caught-branch battle). All of it is deterministic today, but it opens play state and consumes draws on behalf of the dead, and the centralized check would then have to unwind an encounter that should never have started. This phase extends the trap checks' existing principle to every such procedure. The boundary, stated: the invariant bars *new activity*, not the wiping command's own completion bookkeeping — the relocation events of the chute that killed en route still emit (the bodies genuinely moved), the time the fatal action cost still passes and its `TimeAdvancedEvent` still lands, and a fatal rest still reports itself; what never follows a wipe is a fresh procedure with fresh draws. No existing golden reaches any of these paths (nothing in them wipes), so behavior is unchanged for every living party.

## Scope

In scope:

- `SessionMode.VICTORY`, a `terminal` property on the enum, and the legality census: play commands illegal in both terminal modes, referee commands legal in both except the three that resume play — `PlaceParty` (illegal in `victory` only) and `SpawnMonsters`/`SpawnNpcParty` (illegal in both)
- The centralized, edge-triggered wipe check in `GameSession.execute`, and battle's defeat transition folding into it
- Wiped-party guards on the exploration and encounter procedures that would otherwise initiate new activity for a dead party
- The phase golden (a scripted trap wipe replaying and restoring clean), `tests/test_terminal_modes.py`, docs, the one-sentence spec amendment, and the changelog

Out of scope (deferred to the phase or track that picks each up):

- **The transition into victory** — phase 15: completing a concluding quest is the only entrance, `AdventureCompletedEvent` and the authored completion narrative ride it, and nothing in this phase constructs a path into the mode. Tests assign `session.mode = SessionMode.VICTORY` directly, the same direct-state posture the battle tests already use for hit points; shipping a transition surface nothing can call would be dead accommodation code.
- **Post-victory play** — out of scope by spec decision; this phase's resume-play exclusions are what keep the door shut so a post-victory mode can arrive additively later.
- **The `game_over` salvage exits** — `PlaceParty(town)` → `raise_dead` is documented, deliberate, and untouched; this phase adds the non-battle *entrances* to `game_over` and closes exactly one exit that was never salvage (spawning an encounter onto corpses), argued above.
- **New rejection codes, events, or message templates** — none needed, pinned: `session.command.wrong_mode` already carries the mode value, `GameOverEvent` and its `session.game_over` template exist, and the reason string is unchanged. The docs drift gates see nothing new.
- **A `Ruleset` flag** — terminal-state routing is engine correctness, not an optional rule or adaptation; there is nothing to configure.
- **Death records, revival windows, and `raise_dead` mechanics** — consumed as-is by the salvage tests, modified nowhere.

## Work items

### 1. The mode and the legality census — `crawl/commands.py`

- `VICTORY = "victory"` joins `SessionMode`, wire value lowercase like its siblings. The enum docstring grows the terminal-modes note: `game_over` and `victory` end the session — play commands are illegal, referee commands remain legal except those that would resume play, and neither mode is ever left by play (the referee salvage door out of `game_over` is `PlaceParty`, documented there).
- A `terminal` property on the enum — `self in (SessionMode.GAME_OVER, SessionMode.VICTORY)` — because "is the session over" is a question the wipe check, the span-truncation rule, phase 15's transition, and any front end all ask; putting it on the enum gives it one home with no new module-level export. `_ALL_MODES` and `_FIELD_MODES` are import-time computations and need no edit.
- The resume-play carve-outs, each with its docstring carrying the rationale: `PlaceParty.allowed_modes = _ALL_MODES - frozenset({SessionMode.VICTORY})` — a concluded adventure cannot be resumed, while `game_over` remains listed because teleporting the fallen party to town is the first step of the documented revival flow; `SpawnMonsters.allowed_modes` and `SpawnNpcParty.allowed_modes` become `_ALL_MODES - frozenset({SessionMode.GAME_OVER, SessionMode.VICTORY})` — spawning opens an encounter, an encounter is play, and a terminal session opens no new play state (the salvage flow never needs a spawn: its door is `PlaceParty`, and a session salvaged to `town` can spawn again the moment it re-enters a dungeon). Their `Modes:` lists shrink accordingly.
- The docstring sweep: the module docstring's "Referee commands are legal in every mode" universal (and the same opener on the three carved-out commands) rewords to the except-resuming-play form; every referee command that hand-lists its modes (`GrantItem`, `GrantCoins`, `AwardXP`, `SetFlag`, `SpawnMonsters`, `SpawnNpcParty`, `SetDoorState`, `AdvanceTime`, `RollDice`, `IdentifyItem`) gains or adjusts its list — the docs gate (`test_documented_modes_equal_allowed_modes`) enforces exact agreement, so the sweep is mechanical and checked; play commands' lists are already exact and change nowhere.

### 2. The centralized wipe check — `crawl/session.py`

- In `execute()`, after the handler succeeds and immediately beside `_record_deaths` — before the event log extends and before listeners run: if the mode is not terminal, the command's events contain a `DeathEvent` whose `target_id` is a party member, and `party.living_members()` is now empty, then clear `battle` and `encounter`, set `mode = SessionMode.GAME_OVER`, and append `GameOverEvent(reason="the party has fallen")` to the command's events. One walk serves both bookkeeping steps — `_record_deaths` already identifies exactly the member-death events the trigger needs.
- Placement pins, each deliberate: before the log extend, so the event is in the log and in the `CommandResult` like any handler event; before listeners, so a quest tracker or narrator sees the session end in the same result; after the handler, so every death source — trap, falling, deprivation, poison tick, battle, and any future one — routes through a check that never needs to know it exists. A referee command that kills (an `AdvanceTime` that lets poison finish the last member, in town or anywhere else) wipes exactly like a play command, from any non-terminal mode.
- The terminal-mode skip is the victory-stickiness rule: a party that dies *after* victory (a referee advances time and a lingering poison resolves) stays in `victory` with no `GameOverEvent` — the session already concluded, and terminal modes never transition again. The same skip makes the check idempotent in `game_over`: further deaths among the already-fallen emit no second ending.
- The NPC boundary holds for free: `DeathEvent`s for monsters and NPC adventurers carry non-member ids and never trigger the walk's member test, exactly as `_record_deaths` treats them today.
- The reason string lives once, in the check — see the next item.

### 3. Battle's defeat transition folds in — `crawl/battle.py`

- `_check_ends`'s defeat branch keeps everything battle-specific — detecting the wipe, clearing `battle` and `encounter`, returning `[BattleEndedEvent(code="battle.ended.defeat")]` so every caller stops the round — and drops the mode flip and the `GameOverEvent`, which the session-level check now appends. The mode a caller observes after `execute()` returns is unchanged (`game_over`), and the event stream is unchanged at every seam anything asserts: all five call sites tail-position the end events (verified in this plan's research: `start_battle` twice, the resolve-round handler's block loop, slow-attacks pass, and end-of-round pass all `return` or `break` immediately after extending), so under `ResolveBattleRound` the centrally appended event follows `BattleEndedEvent` exactly where the in-handler emission sat. The one mid-command corner that moves — a keyed ambush's free-round TPK inside `MoveParty`, where `GameOverEvent` now lands after the accrual events instead of before — is unasserted anywhere and recorded in fact 4.
- This is the greenfield move, stated: two code paths that set `GAME_OVER` and construct the same event with the same prose would be the duplication `AGENTS.md` bans; the spec's "terminal-state machinery opened once for both changes" is an instruction to build it once.
- `test_tpk_sets_game_over` passes unchanged (it asserts the mode and the code's presence); no golden stores a TPK, so no regeneration.

### 4. Wiped-party guards — `crawl/exploration.py`, `crawl/encounter.py`, `crawl/session.py`

- The invariant, pinned: **once no member lives, no procedure initiates new activity within the same command** — no new encounter, no new discovery, no further cadence; the wiping command's own completion bookkeeping (relocation, time, its primary event) stands, per fact 5. The guard census:
    - `_area_treasure_check` and `_keyed_encounter_check` gain the head guard `_room_trap_check` and `_door_trap_check` already have — no living members, no procedure. Corpses discover nothing and nothing ambushes them.
    - `_end_of_round` and `_pursuit_round` (`encounter.py`) guard immediately after their round advance: when the advance leaves no member living, return its events with no stance action, no reaction re-roll, no distraction draw, no gap update, and no caught-branch battle — a battle among corpses would instantly return `battle.ended.defeat` for a wipe that was never a battle, the exact unwind-an-encounter problem the guards exist to prevent.
    - The per-turn loop in `GameSession.advance_turns` stops the span at a wipe: within each iteration, after the ledger advance and before the rest and wandering cadences, the span breaks when no member lives *and the mode is not terminal*. The non-terminal condition is load-bearing, not decoration: during a wiping command the mode is still a play mode (the central check flips it only after the handler returns), so a deprivation wipe twenty turns into a night's rest truncates at the wipe — the fatigue cadence, the wandering cadence, and the remaining rest all belong to the living — while a referee `AdvanceTime` in `game_over` runs its span in full, because the salvage clock must keep moving: `raise_dead`'s revival window is measured in elapsed time, and a truncation keyed on "no living members" alone would freeze the very clock the revival flow reads. `wandering_check` itself needs no internal guard — the loop breaks before the cadence runs, and a second guard inside the check would be dead code with one caller.
- The guards are behavior-invisible to every session that keeps a living member — every existing golden and test — because each guard's condition is reachable only after a wipe, and they are what keeps the centralized check simple: it never has to unwind play state opened on behalf of the dead, and the event stream after the last death reads as an ending followed by the command's own closing bookkeeping, never as corpses starting something new.
- Draw-sequence note for the record: on the wiped paths these guards *do* change which draws would have occurred after the wipe (no treasure generation, no keyed-encounter spawns, no wandering roll, no reaction re-roll, no distraction die), which is exactly the point — and no stored golden or fixture reaches a wiped state, so nothing regenerates.

### 5. Docs and spec impacts — applied with the implementation PR

- **`docs/spec.md` gains one sentence-level amendment**: the "Victory and session end" paragraph's "play commands are illegal, referee commands remain legal" qualifies the referee clause with the resume-play carve-out (teleporting the party, spawning an encounter), keeping "which is also what lets rewards land after the transition" intact — the reward surface is untouched. This crossed the below-spec-altitude line the moment it became three commands a front end would mispredict from the current sentence; the amendment rides the implementation PR per the phase-loop convention. Everything else in the section already states this phase's contract in the present tense, and the roadmap entry exists.
- **`docs/adaptations.md` gains no entries**, stated deliberately: session modes have no SRD basis — B/X has no session, no terminal state, and no rule this phase reinterprets. The register's silence is the phase 10 and 11 precedent.
- **`docs/guides/sessions-commands-events.md`**: the "small, closed set" sentence and the mode-gating paragraph gain `victory`; the referee paragraph gains the asymmetry — referee commands run in both terminal modes except the three that resume play, with `PlaceParty`'s `game_over` exception named as the salvage door (the existing "referee correcting the world" sentence stays, now explicitly about that flow); the modes-form-a-loop paragraph gains the second terminal ending with a forward note that the transition into `victory` arrives with the authored-quest layer, plus the non-battle wipe sentence — a trap or starvation ends the session exactly as a lost battle does.
- **Docstrings**: `GameOverEvent`'s "(TPK)" parenthetical widens to any party wipe; `GameSession.execute` documents the wipe check among its bookkeeping; `advance_turns` documents the truncation rule and its terminal-mode condition.
- **`CHANGELOG.md`** `[Unreleased]`: an Added bullet for `SessionMode.VICTORY`, the `terminal` property, and the legality contract including the resume-play carve-outs; a Changed bullet for `SpawnMonsters`/`SpawnNpcParty` no longer executing in `game_over` — spawning an encounter onto a wiped party was never salvage, and the encounter it opened put a concluded session back in play modes; a Fixed bullet for non-battle party wipes — previously a party that died to a trap, a fall, poison, or starvation left the session in `exploring` (or `town`, or `encounter`) forever, executing nothing but referee commands yet never ending; now every wipe routes to `game_over` with the same `GameOverEvent` a lost battle emits. No release work item — bullets ride `[Unreleased]` per the cadence.

### 6. Tests — `tests/test_terminal_modes.py` (new) and the phase golden

- **The legality census, restated completely rather than patched**: for every class in `ALL_COMMAND_CLASSES`, terminal-mode membership follows referee-ness with the three resume-play exceptions — play commands' `allowed_modes` are disjoint from both terminal modes, referee commands contain both except `PlaceParty` (contains `game_over`, not `victory`) and the two spawn commands (contain neither). The existing `test_referee_commands_are_legal_everywhere` restates around the carve-outs, and its `REFEREE_COMMANDS` set gains the two members it silently omits today (`identify_item`, `spawn_npc_party`) so the census is total.
- **Victory legality at the executed seam**: with `session.mode = SessionMode.VICTORY` assigned directly, a play command sweep rejects `wrong_mode` (params carrying `"victory"`), the referee surface (`GrantItem`, `AwardXP`, `SetFlag`, `AdvanceTime`, `RollDice`) executes accepted, and `PlaceParty`, `SpawnMonsters`, and `SpawnNpcParty` reject `wrong_mode`.
- **Victory stickiness**: in `victory`, a lingering poison finishing the whole party under a referee `AdvanceTime` leaves the mode `victory` and emits no `GameOverEvent` — the terminal skip pinned from the victory side.
- **Non-battle wipes, one per entrance**: a trap wipe (`MoveParty` onto a springing `kills` trap with `affects="party"`) ends in `game_over` with the `GameOverEvent` in tail position and `battle`/`encounter` cleared; a deprivation wipe (flag on, tracks pre-set to the damage threshold, members at 1 hp, `AdvanceTime` across the day boundary); an encounter-mode wipe — pinned on a *hostile-deadline* stance with poison resolving during a `Wait` round, so the `_end_of_round` guard is load-bearing: the corpse battle must not start, and the session ends in `game_over` with the encounter cleared; a town wipe (poison under `AdvanceTime` while in `town`). Each asserts the mode, the event, and — the edge-trigger pin — that a *subsequent* referee command among the corpses emits no second `GameOverEvent`.
- **The salvage flow, end to end**: TPK → `PlaceParty(town)` accepted with mode `town` and **no** re-triggered game-over (the level-vs-edge distinction made load-bearing) → `GrantCoins` → `PurchaseHealing(service="raise_dead")` revives → `EnterDungeon` accepted. Beside it, the salvage clock: a referee `AdvanceTime` in `game_over` advances its full span (the truncation rule's terminal-mode condition pinned from the side that needs it), and a `SpawnMonsters` in `game_over` now rejects `wrong_mode` — the Changed bullet's fence.
- **Guards**: a chute trap that kills the party mid-slide arrives without discovering the destination cache or opening its keyed encounter; a wiped party's span truncates in `advance_turns` (clock stops at the wipe turn, no wandering roll after); a pursuit-round wipe resolves no distraction draw, no gap update, and no caught battle.
- **Persistence**: `save`/`load` round-trips both terminal modes; a loaded `victory` session still enforces its legality.
- **The golden** — `tests/generate_phase12_goldens.py`, `tests/goldens/phase12_wipe.json`, `tests/test_phase12_goldens.py`, on the phase 11 pattern (the test imports the generator's build/run). A small authored dungeon whose second cell carries a `kills=True, affects="party"` gas trap with no save; the seed is chosen so the 2-in-6 spring fires on entry, so the wipe is scripted, not lucky. The scripted run: enter, step, die — mode `game_over`, `GameOverEvent` last — then two accepted referee probes (`RollDice`, `SetFlag`) proving the terminal session still executes and logs referee commands. Replay of the accepted log reaches identical final state, and `load(save)` equals `replay(seed, commands)` — the standing equivalence guarantee now covering a session that *ends*, which no existing golden does.
- The full gate green: `uv sync && uv run ruff format --check && uv run ruff check && uv run pyright && uv run pytest && uv run mkdocs build --strict`.
